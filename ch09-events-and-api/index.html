事件與 $ API：介面、指令、提示與分叉

事件、指令、提示與分叉怎麼用

第 8 章你已經手寫出 plugin.json、hooks.json 與 register。這一章把視角拉到 register 裡面：on 可以掛哪些事件、$（mods API）能呼叫什麼。本章依序看四件事：畫介面、加指令、動提示、分叉模型呼叫。清單以官方 Mods reference（v2.1.290）為準，你的版本實際有哪些事件與方法，以 Claude Code 寫進 .claude-plugin/types/ 的型別宣告為準。

事件地圖

事件依關注的對象分組。每個 hook 能回傳什麼因事件而異，下表只列各組的代表。

分組代表事件hook 可以回傳
工具tool.call、tool.check、tool.describetool.call 可回 next(e)、{ deny: reason }、{ result }；tool.check 回 { decision }；tool.describe 回 { description }
提示prompt.submit、prompt.section、prompt.context、skill.promptnext({ ...e, text })、{ drop: reason }、{ text }、{ blocks }
指令與設定command.run、command.describe、config.set{ text }、{}、{ deny: reason }
回合turn.start、turn.step、turn.completenext(e)；turn.complete 可回 { text } 在答案下方多顯示一行
工作階段session.start、session.end、session.compactnext(e)、{ skip: reason }
子代理agent.offer、agent.spawn{ isOffered: false }、{ deny: reason }
介面ui.render、ui.press、ui.input、ui.selectui.render 回一棵元素樹
其他 modplugin.register、engine.create{ refuse: reason }、加上 namespace 的 mods API

還有兩類事件容易漏看。一是設定檔裡的 settings hook：每個都有對應的 classic.<Event>，例如 classic.Stop。二是 mods API 的每個方法本身也是事件，例如 fs.read、ui.open，排在前面的 mod 可以觀察、改寫或拒絕後面 mod 的呼叫。

on 的第二個參數是 matcher，欄位值可以是字串、陣列或正規表示式，所有欄位都符合才會執行 hook：

matcher：三種寫法
// A string matches one value: Bash calls only
on('tool.call', { tool: 'Bash' }, hook)
// An array matches any value in it: Edit calls and Write calls
on('tool.call', { tool: ['Edit', 'Write'] }, hook)
// A regular expression matches by pattern: every tool of one MCP server
on('tool.call', { tool: /^mcp__github__/ }, hook)

事件名稱也能用萬用字元：'classic.*' 比對所有 settings hook 事件，'*' 比對除了 telemetry 事件以外的所有事件。同一個事件沒有 matcher 就不能註冊兩次，否則模組載入失敗，錯誤是 on("session.start") is registered twice without a matcher。

介面：用 ui.render 畫在 Claude Code 裡

Claude Code 把畫面上每個可擴充的位置叫做 render site，每個 site 對應一次 ui.render 事件，e.component 是 site 的名稱，e.props 是它的資料，e.surface 是 terminal 或 desktop。常用的 site 有：

  • AbovePrompt：輸入框上方的色帶，props 有 hasSurvey、isWorking、maxRows、bodyColumns
  • Pane：跟逐字稿並排或內嵌的面板，由 $.ui.open 開啟
  • Spinner、UserMessage、AssistantMessage、ToolUse 等：改寫 Claude Code 原本就會畫的內容
💬

畫面上的每個位置都是共用的：hasSurvey 為真就讓給問卷，沒東西可畫就用 next(e) 還回去，只有真的有話要說時才佔用它。

元素不是全域變數。終端機與桌面版支援的元素略有不同，所以要用 $.ui.resolve(e) 取得當下 surface 能畫的元素建構函式，再組出 Box、Text、Button、Input、Select、Code、Markdown 等。Svg 只有桌面版畫得出來，Raster 與 Image 只有終端機畫得出來。下面這個 hook 取自第三方教學的 edit-count 範例，read 與 edits 是同一個模組開頭 import 與宣告的 state：

edit-count 的 ui.render hook
on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
  const n = await read($, edits)
  if (n === 0 || e.props.hasSurvey) return next(e)
  const { Box, Text } = $.ui.resolve(e)
  return Box({
    paddingX: 1,
    children: [Text({ color: 'cyan', children: 'Files edited this session: ' + n })],
  })
})

三個細節在每個畫面類 mod 都適用：hasSurvey 為真時是問卷要用這個位置，所以讓出去；沒東西可畫時回 next(e)，把位置還給 Claude Code 與其他 mod；寬度要讀 e.props.bodyColumns，並排面板時它比終端機視窗窄。面板若沒有被使用者主動要求，要寬 144 欄才會自動開（使用者開過一次之後降到 110 欄），空間不夠時 $.ui.open 回傳的 isPlaced 會是 false，這時改畫在色帶上。

不需要畫面、只想給使用者一點訊息時，有三個呼叫：$.ui.status(text) 在輸入框下方放一行常駐文字，$.ui.toast(text) 跳幾秒的通知，$.ui.log(text) 在逐字稿加一行 Claude 不會讀的暗色文字。

⚠️
不是每個地方都畫得出來

mod 的 hook 在 VS Code 擴充套件的對話面板與 claude -p 都會執行，但這兩處不會畫出任何 mod 的介面。需要「一定看得到」的訊息時，改用指令回傳的 text 或逐字稿裡的一行。

指令：給使用者的 slash command

指令是給使用者用的。流程固定兩步：在 session.start hook 裡用 $.command.register 登記，再用 matcher 限定只處理這個名稱的 command.run。Claude Code 會等 session.start 跑完才處理第一個 prompt，所以登記的東西從第一輪就可用。

加一個 /standup 指令
on('session.start', async ($, e, next) => {
  // Add /standup to the command list, with the description the user sees there
  await $.command.register({ name: 'standup', description: 'Summarize what changed today', argumentHint: '[days]' })
  return next(e)
})

// The matcher limits the hook to /standup, so other commands don't reach it
on('command.run', { command: 'standup' }, async ($, e) => {
  // e.args is the text typed after the command name, or an empty string
  return { text: 'Summary for the last ' + (e.args || '1') + ' day(s): ...' }
})

回傳的 text 會印在逐字稿裡，Claude 也讀得到。指令只想開面板、不想印字，就回 {}；想讓指令在 Claude 工作中也能執行，登記時加 immediate: true。指令名稱只能用英數字、_ 與 -，最長 64 字元。名稱撞到內建指令時 $.command.register 會丟錯，而丟錯的 hook 會被跳過，連後面的程式一起不跑，所以把登記放在 hook 最後，或包 try 與 catch。

想讓 Claude 而不是使用者去呼叫，改用 $.tool.register。Claude 看到的工具全名是 mcp__、plugin 名稱、兩個底線、你登記的名稱，下面這個範例的 plugin 叫 my-mod，所以全名是 mcp__my-mod__ticket：

註冊一個給 Claude 呼叫的工具
on('session.start', async ($, e, next) => {
  await $.tool.register({
    name: 'ticket',
    // Claude decides when to call the tool from this description
    description: 'Look up a ticket by its id and return its title and status',
    // The arguments Claude has to send: one required string named id
    inputSchema: { type: 'object', properties: { id: { type: 'string' } }, required: ['id'] },
  })
  return next(e)
})

// The full tool name is mcp__, the plugin's name, and the registered name
on('tool.call', { tool: 'mcp__my-mod__ticket' }, async ($, e) => {
  // The tool's arguments are fields of e, so the id is e.id
  const response = await $.http.fetch('https://tickets.example.com/api/' + encodeURIComponent(e.id))
  // Return a result either way, so Claude learns when the lookup failed
  return { result: response.ok ? response.text : 'Lookup failed with status ' + response.status }
})

MCP 工具搜尋可能把工具延後載入，Claude 只看到名稱、看不到描述。要讓它每輪都考慮這個工具，登記時加 isDeferred: false，這個欄位需要 Claude Code v2.1.293 以上，更早的版本會忽略它。

提示：改寫、補充或攔下 prompt

prompt.submit 在每個 prompt 送出前觸發，e.text 是使用者輸入的內容。三種處理方式各有固定的回傳寫法：

想做的事回傳
改寫 prompt（逐字稿與歷史紀錄都顯示新文字）next({ ...e, text: newText })
在 prompt 後面補一段只有 Claude 看得到的文字next({ ...e, context: [...(e.context ?? []), extraText] })
不要送出這個 prompt{ drop: 'the reason' }

下面的範例只在 prompt 提到 PR 時才多花一次 git 呼叫，使用者在逐字稿看到的訊息不變，Claude 則多讀到一行目前分支：

提到 PR 時，替 Claude 補上目前分支
on('prompt.submit', async ($, e, next) => {
  // Pass on a prompt that doesn't mention a pull request as it is
  if (!/\bPR\b|pull request/i.test(e.text)) return next(e)
  const git = await $.process.run(['git', 'branch', '--show-current'])
  // Outside a git repository the command fails, so there's no branch to add
  if (git.exitCode !== 0) return next(e)
  // Keep any context an earlier hook added, and add one more line for Claude
  return next({ ...e, context: [...(e.context ?? []), 'Current branch: ' + git.stdout.trim()] })
})

drop 的原因會顯示給使用者，開頭是 Prompt dropped by a hook:，所以要寫給人看。系統提示與第一則訊息的內容，另有 prompt.section、prompt.context 與 skill.prompt：這些事件的文字若每次請求都不同，會讓 prompt cache 失效。要從背景工作主動開一輪，用 $.prompt.submit({ text })：Claude 會在一句指名你的 mod 為寄件者的話之後讀到這段文字，加 asUser: true 則當成使用者本人說的。它要等工作階段閒置才會開始，resolve 的時機是那一輪開始，所以不要在 Claude 還在工作時的 handler 裡 await 它。

💬

prompt.submit 有三種下手的力道：改寫讓所有人看到新文字，補 context 只讓 Claude 看到，drop 則連 Claude 都看不到。

分叉：替 mod 另外叫一次模型

mod 可以自己向模型發一次小請求，用來分類或摘要。兩個方法差在請求裡帶什麼：

請求內容$.model.complete$.model.fork
模型你傳的 model工作階段目前的模型
system prompt一小段署名區塊，加上你傳的 system工作階段的 system prompt
訊息只有你的 prompt到目前為止的對話，加上你的 prompt
CLAUDE.md 等專案脈絡不含含
工具無帶著 Claude 的工具，但模型無法呼叫

fork 會重送對話的最後一次請求，所以只要對話的 cache 還活著，大部分內容由 prompt cache 提供。社群的 next-steps mod 就是每回合呼叫一次 $.model.fork 建議下一步，成本約一則短回覆。兩個方法都用工作階段的憑證，費用算在使用者自己的方案、API key 或雲端供應商上。

/triage：用 $.model.complete 單發一個 prompt
on('command.run', { command: 'triage' }, async ($, e) => {
  const r = await $.model.complete({
    model: 'haiku',
    // The system prompt sets the job, and the prompt carries the text to label
    system: 'Reply with one word: bug, feature, or question.',
    prompt: e.args,
    // One word needs few tokens, and the call gives up after 15 seconds
    maxTokens: 20,
    timeoutMs: 15000,
  })
  // r.text exists only when the model answered, so check r.isAnswered first
  const label = r.isAnswered ? r.text.trim() : 'unknown'
  return { text: 'Label: ' + label }
})

Claude API 失敗時呼叫不會 reject，所以一定要先看 r.isAnswered，為 false 時原因在 r.reason。只有請求本身不被允許，例如你的組織封鎖了那個模型，呼叫才會 reject。maxTokens 預設 1024。每次呼叫都有一大段固定內容時，把 prompt 改成 { text } 區塊的陣列，在固定內容最後一塊加 cache: true：

把固定的規則放在 cache 斷點之前
on('command.run', { command: 'triage' }, async ($, e) => {
  const r = await $.model.complete({
    model: 'haiku',
    prompt: [
      // Identical on every call, so it forms the cached prefix
      { text: RULES, cache: true },
      // Changes on every call, so it goes after the breakpoint
      { text: e.args },
    ],
  })
  return { text: 'Label: ' + (r.isAnswered ? r.text.trim() : 'unknown') }
})

區塊陣列需要 Claude Code v2.1.292 以上，較舊的版本會直接拒絕。快取存活五分鐘，要延長到一小時要靠使用者設定的 subagentPromptCacheTtl，不是呼叫端能決定的。如果連續兩次呼叫都只寫入、沒讀取，通常是前綴每次不同，或兩次呼叫相隔超過存活時間。

ℹ️
寫法要讓靜態分析看得懂

前面所有範例都把呼叫寫成完整的 $.命名空間.方法，事件名稱也是字串常值。這是 claude plugin validate 能列出你的 mod 動了什麼的前提，不要把 $.ui 指派給變數或解構。下一章會逐條說明，以及怎麼寫測試。

小結與下一章預告

事件決定 hook 何時執行，$ 決定它能做什麼；介面、指令、提示與分叉，剛好對應 ui.render、command.run、prompt.submit 與 $.model.fork 這四組最常用的組合。下一章回到工作流程：寫好之後，怎麼用 claude plugin validate 驗證、用 claude plugin test 測試、用 --debug 除錯，並把成果分享給別人。
