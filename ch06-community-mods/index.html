第 6 章 · Part 2：安裝與使用

社群 Mods 精選與挑選原則

社群已有幾十到上百個 Mod，挑對比裝多更重要

💬

《論語・述而》說「擇其善者而從之」。本書借這句話談挑選社群 Mod：挑對比裝多更重要；本章的挑選標準是看 Mod 的觸及範圍是否與用途相稱，這是本書的標準，不是《論語》原意。

出處：《論語・述而》「三人行，必有我師焉。擇其善者而從之，其不善者而改之。」引用原文；套用到挑選 Mod 是本書改編。

內建 Mod 只有四個，真正的選擇在社群。問題是：Mod 沒有沙箱，裝一個就是讓一段陌生的程式碼以你的權限在 Claude Code 裡跑。這一章先帶你認識目前去哪裡找、第三方文章列舉了哪些 Mod，再整理一套「裝之前看什麼」的流程。

⚠️
本章的數字是 2026 年 10 月初的快照

目錄收錄的數量、星數與各 Mod 的授權狀態，來自第三方文章（Capital & Compute，2026-10-02 發表，GitHub 資料讀於 10 月 4 日）。這個生態每天都在變，書中的數字只用來說明規模與差異，安裝前請以倉庫現況為準。

去哪裡找：沒有官方 Mod 專區

依該文章的整理，Claude Code 目前沒有只收 Mod 的官方圖庫。Mod 以 plugin 的身分出現在 /plugin 與 Claude directory，Anthropic 的官方 plugins 倉庫也沒有把 Mod 獨立出來。探索工作由社群網站承擔，而它們的可信度差很多：

目錄收錄量收錄方式安全資訊
claude-mods.com75 個，8 類每日掃 GitHub，再逐一安裝並對照 README 人工檢查只有分類
awesome-claude-code-mods72 個（來自 142 個候選倉庫）每晚掃描含 hooks module 的倉庫列出每個 Mod 掛了哪些事件、呼叫哪些 API、觸及範圍等級
claudemods.ai45 個，9 類投稿，加上每日票選無

文章的建議是：用 claude-mods.com 看有什麼，再回到 awesome 清單核對這個 Mod 的程式碼能碰到什麼。只有後者在安裝前告訴你「它能動到什麼」。另外還有 claudecodemods.com（與其他類型的外掛混雜）和 claudemod.com（多為 skills 與 MCP），不是專門的 Mod 目錄。

⚠️
來源之間的數字對不上，原因無法核實

另一篇指南（StationX，同樣是 10 月初）把 awesome-claude-code-mods 描述為自動掃描的目錄，10 月 4 日重掃時收錄 1,740 個 Mod；上表引用的文章則是 72 個（統計日期 9 月 17 日）。兩者量級差很多，素材沒有說明統計口徑是否相同，所以本書只引用「趨勢」，不引用單一的「目前總數」。

ℹ️
名稱撞車的陷阱

搜尋「best Claude Code mods」時排第一的 GitHub 倉庫 0xDarkMatter/claude-mods，裝的是 skills、agents、commands 與 settings hooks，不是本書講的 Mod。該文章指出它建立於 2025 年 11 月，只是名稱碰巧相同。

依用途挑：先從「觸及範圍小」的開始

該文章的排序原則是「越不動東西的越先裝」。以下是它列出的幾類，我只轉述它描述過的功能；Mod 的實際行為請以各倉庫為準。

用途Mod文章對它的描述
看花費token-ledger釘一條狀態列顯示 session 成本、上一回合 token 與快取命中率，/ledger 看完整表格；掃描結果只碰它掛的事件，文章建議從這裡開始
看花費budget-guard監看 session 金額與 5 小時、7 天兩個方案視窗，80% 警告一次，超過後預設拒絕工具呼叫；倉庫當時沒有授權檔
擋機密secret-redactor在模型讀到之前，把機密、email、IP 換成固定佔位符，回到工具呼叫時再還原，指令仍可執行；MIT
擋機密git-gates除非你最近一則訊息這麼說，否則拒絕 commit、push、merge；文章說它沒有星數也沒有授權，當作可以抄的做法而非依賴對象
改介面cc-pr-tracker在提示符上方顯示追蹤中的 PR 狀態；會呼叫 GitHub API，因此需要網路

想學寫法的話，Anthropic 在 anthropics/claude-code-playground 的 claude-code/mods 放了三個範例 Mod，StationX 的指南列出它們是 blast-radius（攔下危險指令並顯示影響範圍）、token-weather（提示符上方一行的 context 用量預報）與 replay-theater（用 /replay 逐步看上一回合的檔案變更）；它說每個 README 的「How it was built」都寫到哪些做法行不通，是很好的學習材料。

再往上是「每天可能用到、但觸及範圍也大」的一群。文章點名的有 plan-progress（把計畫畫成提示符上方的進度條）、cc-changelog（/whatsnew 開 changelog 面板，並會連到第三方 changelog 網站）、terminal-browser（在面板裡跑完整的 Chromium，文章稱它是這類裡觸及範圍最廣的之一）、worktree-map（用唯讀 git 指令列出 worktree）。另外 lcm 與 storybloq 會看到每一個工具呼叫，lcm 連系統提示與每則 prompt 也看得到，文章把它們放在最後。

觸及範圍：一個比星數更有用的指標

文章引用 awesome 清單的掃描（統計區塊日期 2026-09-17，對應 Claude Code 2.1.274）：72 個 Mod 裡，只需要「繪圖與記憶」的有 20 個、會讀檔的 6 個、會寫檔／跑程序／驅動 Claude 的 32 個、會連網的 14 個。換句話說 72 個之中有 46 個能寫檔、跑程式、驅動 Claude 或連網。文章也提醒：觸及範圍只是足跡，不是定罪。PR 追蹤器本來就得呼叫 GitHub，遮蔽器本來就得讀工具輸出，要問的是觸及範圍和工作是否相稱。

挑選原則：安裝前四件事

一、先用 validate 看它宣告了什麼

官方管理員文件給的做法，是在不執行 Mod 的前提下，對 plugin 資料夾跑 claude plugin validate：

bash
claude plugin validate ./some-mod

# 輸出裡的兩行（官方文件的範例）
# ❯ ./register.js hooks: session.start, tool.call, ui.render{component=Pane}
# ❯ ./register.js calls: $.fs.read, $.http.fetch, $.store.set, $.ui.open

hooks: 那一行是 Mod 接收的事件，calls: 是它的程式碼呼叫了哪些 $ 方法。官方列出幾個要特別留意的呼叫，例如 $.fs.read／$.fs.write（在你能碰的任何位置讀寫檔案）、$.process.run／$.process.spawn（以你的身分啟動程式）、$.http.fetch（發網路請求）、$.env.get／$.settings.read（讀環境變數與設定，那裡可能放著 API key）、$.model.complete（用你的方案或 API key 呼叫模型）。官方也寫明：Claude Code 會拒絕載入一個「用了這個指令讀不出來的方式去用 mods API」的 Mod。

🚫
validate 不等於安全

一個收錄 50 個 Mod 的倉庫自己的資安說明就寫著：claude plugin validate 會列出事件與引擎呼叫，但不能證明 Mod 是安全的。它是審查的輔助，不是判決，原始碼還是要自己讀。

二、要求觸及範圍和用途相稱

一個只畫狀態列的 Mod 如果同時在啟動程序，就值得問為什麼。這也是為什麼前面的表格把「看花費」放在最前面：成本計量本來就只需要掛事件、不需要碰檔案。

💬

最小權限原則（Principle of Least Privilege）搬到 Mod 上：只畫狀態列的，就不該碰檔案、啟動程序或連網。

出處：J. H. Saltzer、M. D. Schroeder，〈The Protection of Information in Computer Systems〉，《Proceedings of the IEEE》63(9)，1278–1308，1975，I.A.3「Least privilege」；以 Mod 的用途判斷所需權限是本書改編。

三、釘住你審查過的版本

文章的建議之一是釘住你看過的版本：執行時才下載程式碼的 Mod，在你讀完之後仍可能改變。這是它指出的、早期安全分析提到的風險中「至今沒變」的一項；其他幾項（例如偽造權限提示）依文章所述，文件現在已說明 Mod 不能改寫權限提示的樣式。

四、知道關閉的方式

官方 overview 與文章給出三層開關：在 /plugin 的 Installed 分頁停用單一 Mod；claude --safe-mode 讓單一 session 不載入任何已安裝的 Mod（它也會停用你的其他自訂內容）；"disableAllHooks": true 全面關閉。這些都不影響內建 Mod，上一章已說過。

實際安裝一個

Mod 與一般 plugin 的安裝流程相同，來源通常是帶有 marketplace 檔的 GitHub 倉庫：

Claude Code 內
# 在 Claude Code 裡（需要 2.1.287 以上）
/plugin marketplace add <owner>/<repo>
/plugin install <mod-name>@<marketplace-name>
/reload-plugins
/plugin          # 分頁下方的暗色一行會列出啟用中的 mods

以我自己用的 next-steps 為例，它來自社群 marketplace，終端機版的指令如下：

bash
claude plugin marketplace add anthropics/claude-plugins-community
claude plugin install next-steps@claude-community

我在安裝前讀過它的原始碼：register.tsx 約 230 行，只用到 $.command.list、$.model.fork、$.prompt.fill、$.prompt.suggest，沒有連網、不執行外部指令、不讀寫檔案；代價是每回合一次 $.model.fork。這樣的審查結果（呼叫清單短、全是介面與提示類）正是前面所說「範圍與用途相稱」的樣子。它的行為細節留到第 14 章。

倉庫宣稱的測試，可以自己重跑

另一篇文章驗證某個 50 個 Mod 合集時，用的就是這兩條指令。合集宣稱通過 50 次 strict 驗證與 250 個原生測試，作者在全新 clone 上重跑，結果一致：

bash
claude plugin validate mods/<name> --strict
claude plugin test mods/<name>

我們自己下載 Mod 之後也可以這麼做：validate --strict 檢查結構，plugin test 跑它自帶的測試。沒有測試的 Mod，品質訊號就少了一個。第 10 章會再詳談測試。

小結

  • 沒有官方 Mod 專區；claude-mods.com 適合逛，awesome-claude-code-mods 適合安裝前審查，因為只有它列出觸及範圍。
  • 先裝觸及範圍小的（成本計量、遮蔽、小介面），再考慮瀏覽器、記憶這類會看到每個工具呼叫的重型 Mod。
  • 流程：validate 看 hooks: 與 calls: → 讀原始碼 → 釘版本 → 知道怎麼關。
