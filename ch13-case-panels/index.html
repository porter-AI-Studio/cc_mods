面板類 Mod：用量儀表、快取倒數、遮罩與待辦

面板 Mod 的四種視覺化應用

上一章的守門器負責「擋」，計量條負責「量」。這一章把焦點放在另一類最常見的 Mod：把平常要打指令才看得到的資訊，一直放在眼前。2026 年 10 月 6 日有人掃過社群目錄，共 2692 個 Mod（第 12 章 Kanaries 提到約 2,690 個，兩個來源口徑不同，都不是官方統計）；影片作者用名稱與說明粗略分類（他自己註明數字不精確、只看排名），最多的一類就是「顯示用量與 Context 的儀表」，遠多於第二名的對話交接與第三名的危險指令攔截。本章挑四個面板類案例：用量儀表、快取倒數、錄影遮罩、待辦清單，並說明它們依賴哪些 API、有哪些限制。

畫在哪裡：band 與 pane

面板類 Mod 靠 ui.render 事件工作：Claude Code 要畫某個「render site」時會問 Mod，Mod 回傳一棵由 Box、Text、Button、Input 等元素組成的樹。兩個最常用的位置是 AbovePrompt（輸入框上方的細帶，本書稱 band）與 Pane（開在對話旁邊的側邊面板）。依官方 Mods reference，這兩個 site 在 Terminal 與 Desktop 都會渲染。

下面是 wmedia.es 作者為自己的 craft 外掛做的狀態列（一行顯示作業、階段、進度方塊與正在跑的 agent）裡的 ui.render 掛法，原文共五個 hook，這裡只取畫面那一個：

hooks/register.ts（craft bar，節錄）
on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
  const line = pieces(state, await $.clock.now())
  if (e.props.hasSurvey || line.length === 0 || (await hidden($))) return next(e)
  const { Box, Text } = $.ui.resolve(e)
  const below = await next(e)
  const texts = line.map(piece => Text({ ...STYLES[piece.tone], children: piece.text }))
  return Box({ flexDirection: 'column', children: [Box({ key: BAR, children: Text({ children: texts }) }), below] })
})

注意三個細節。第一，e.props.hasSurvey 為真就直接 return next(e)，讓位給 Claude Code 自己的問卷。第二，先 await next(e) 拿到原本會畫的內容，再把自己的那一行疊在上面，這樣不會蓋掉別的 Mod。第三，元素不是自己 import，而是從 $.ui.resolve(e) 取得。

⚠️
不是每個介面都看得到

多份來源一致指出：band 與 pane 只畫在終端機與 Claude Desktop 的 Code 分頁；VS Code 擴充套件的對話面板與 claude -p 會執行 hook，但不畫任何東西。作者自己的環境也實測過同樣結果（見下一章）。所以面板類 Mod 最好像 IT-Connect 文章裡的新聞面板範例那樣（在 VS Code 擴充套件中直接回傳文章清單），另外準備文字回退，讓指令至少能回傳純文字。

案例一：用量儀表

Claude Code 本來就有 /context 與 /usage，缺點是你得想到才會去打。用量儀表把三個數字常駐在輸入框上方：Context 用了幾 %、5 小時額度用了幾 % 與重置時間、本週額度用了幾 %，超過八成的那一格轉紅。這個案例出自 YouTube「AI懶人報」EP421（VID-318），影片給的一句話 Prompt 如下：

給 Claude 的 Prompt（取自 EP421）
做一個 Mod，在輸入框上方畫一條細帶，顯示 Context 用了幾趴、5 小時額度用了幾趴、幾點重置、本週額度用了幾趴，每一輪結束更新一次，超過八成的那一格變紅。

資料從哪來？依官方 Mods reference 的 API 表，$.session.usage() 回傳 {`{ startedAt, context, rateLimits, cost }`}：context 有 tokens、window、percent，rateLimits 是 {`{ kind, percentUsed, resetsAt }`} 的清單。下面的草稿只用到這些欄位，是依文件組合出來的示意，我沒有實際跑過，載入前請照第 10 章的流程跑 claude plugin validate 與測試：

示意：用量細帶（作者組合，未實測）
on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
  const u = await $.session.usage()          // { startedAt, context, rateLimits, cost }
  const { Box, Text } = $.ui.resolve(e)
  const cells = [
    { label: 'context', pct: u.context.percent },
    ...u.rateLimits.map(r => ({ label: r.kind, pct: r.percentUsed })),
  ]
  const texts = cells.map(c =>
    Text({ color: c.pct >= 80 ? 'red' : undefined, children: c.label + ' ' + c.pct + '%  ' }))
  return Box({ flexDirection: 'column', children: [Text({ children: texts }), await next(e)] })
})

影片也提醒一件事：如果你用的是 API Key，就沒有 5 小時與每週額度，要把那兩格改成「這個對話目前花了多少錢」，也就是改讀 cost。OneWave AI 開源的 burn-meter 是同類的完整版：輸入框上方有一條花費的火焰條，旁邊的 pane 顯示 5 小時與每週額度和重置時間（他們自述這是最常看的一個，理由是「看得見的花費才管理得了」）。explainx.ai 的 Context Meter 則是側邊 pane 版：他們在 Claude Code 2.1.288 的真實 session 裡截到 6.0% 已用、1,000,000 token 視窗中用掉 58,590，並指出一輪空話之後基線不是零，因為系統提示、工具定義與已安裝的 skills 都佔了 context。

💬

OneWave AI 說「看得見的花費才管理得了」：用量儀表的價值，不在多一個數字，而在不必再想到才去打 /usage。

出處：OneWave AI（The OneWave Team），〈Claude Code Mods: What They Are, and the Ten We Open-Sourced〉，2026，burn-meter 小節；原文為「spend you can see is spend you manage」。中文為本書轉述；後半句是本書改編。

案例二：快取倒數

Claude 會把對話前面的內容存進 prompt cache，下一句不必從頭計算；快取有期限，離開座位回來可能已經過期，下一句就得整段重算、額度掉得很快。快取倒數 Mod 記住「Claude 上一次回答完的時間」，在輸入框上方倒數，剩 5 分鐘時提醒，過期就轉紅並提示是否先交接到新對話。

💬

快取倒數的起點，是 Claude 上一次回答完的時間，不是你離開座位的時間；期限是 1 小時還是 5 分鐘，請打 /usage 看，別抄流傳的數字。

這裡有個到處流傳的數字要小心。EP421 的說法是：依官方文件，訂閱方案且用量仍在方案內含範圍時，主對話的快取為 1 小時；用 API Key 或已超出方案、開始用額外用量時預設只有 5 分鐘；Subagent 的請求預設也是 5 分鐘；不確定時打 /usage，裡面會寫你的快取是 1 小時還是 5 分鐘。所以 Prompt 裡的期限要照自己的情況填：

給 Claude 的 Prompt（取自 EP421，期限依自身情況填寫）
做一個 Mod，記住主對話最後一次送給模型的時間，也就是 Claude 上一次回答完的時候，在輸入框上方倒數快取還剩多久過期。我的快取是一小時，Subagent 的請求不算。剩 5 分鐘的時候提醒一次，已經過期的話那一格變紅，寫「下一句會重新計算」。

另一支影片（Sen's Sense AI，VID-319）的 Cache Watch 面板則顯示他的剩餘 58 分鐘，並同時列出 5 小時與本週的 token 用量；當 session 已有快取時這條 bar 會自動彈出，快取快過期又暫時不想回覆時，可以按 Handoff 先做摘要，讓下一個 session 接得上。實作上，倒數靠定時器重畫。官方文件的 $.clock.every 範例如下（每分鐘查一次 PR checks 並更新輸入框下方一行）：

$.clock.every 與 $.ui.status（官方文件原文）
on('session.start', async ($, e, next) => {
  // Call the function every 60,000 milliseconds, starting one minute from now
  $.clock.every(60_000, async () => {
    const status = await $.process.run(['gh', 'pr', 'checks', '--json', 'state'])
    // Replace the line under the prompt with the latest summary
    $.ui.status('checks: ' + summarize(status.stdout))
  })
  // Return without waiting for the timer, so the session starts right away
  return next(e)
})

倒數 Mod 的做法就是把回呼換成「現在時間減去上次回答完成的時間」，再用 $.ui.invalidate('ui.render') 要求重畫。官方 limits 表寫明：重畫節流為每秒 10 次，終端機中對可見 pane、展開的 band 與提示下方的 hint 行是每秒 30 次，更密的呼叫會被合併。以分鐘為單位的倒數遠低於這個上限，不必擔心畫面閃爍。

ℹ️
狀態放哪裡

OneWave AI 的經驗是：hot reload 會重置模組自己的變數，畫面要讀的值應放在引擎保管的狀態裡，否則每次改檔 pane 就變空白。官方 API 表中對應的是 $.state（響應式狀態）與 $.store（本機所有 session 共用的 JSON 鍵值儲存，總量 4 MiB）。

案例三：錄影遮罩

開會分享畫面或直播時，最怕畫面突然出現 API Key 或客戶 Email。EP421 的第四個 Mod 加一個 /record 指令：打開後，畫面上你輸入的訊息、Claude 的回答、執行的指令與工具結果裡，Email、API Key、電話號碼都換成遮罩，再打一次就關閉。關鍵是「只改畫面」：Claude 讀到的仍是原內容，工作不受影響。

給 Claude 的 Prompt（取自 EP421）
做一個 Mod，加一個 /record 指令，打開之後畫面上我打的訊息、Claude 的回答、它執行的指令跟工具結果裡面，Email、API Key、電話號碼都換成遮罩，再打一次 /record 就關掉。只改畫面，不要改 Claude 讀到的內容。

這類 Mod 靠的是 ui.render 的另外幾個 site：依 Mods reference 的 render site 表，UserMessage、AssistantMessage、ToolUse、ToolResult、CommandOutput 都可以被 hook 改畫。Sen's Sense AI 的 Recording Mask 在畫面下方放一顆紅色 recording 按鈕，按 off 只是關掉遮罩處理，並不是結束錄影。

EP421 還交代了兩個限制，寫給別人看的時候不要略過：第一，全螢幕的詢問框（權限確認）依官方規定 Mod 不能改，裡面的指令若含 Key 仍會露出來；第二，若你的要求是連 Claude 都不要看到原始值，那是另一種 Mod，要在工具結果交給 Claude 之前就先折掉，跟「只遮畫面」是不同層級的事。後者能做什麼、該不該做，第 15 章談安全時再回頭討論。

💬

錄影遮罩遮的是觀眾的眼睛，不是 Claude 的眼睛：只改畫面，Claude 讀到的仍是原內容。

案例四：待辦清單

待辦是面板裡少數需要輸入與持久化的案例。explainx.ai 的 awesome-claude-code-mods 收了 50 個 MIT 授權的 Mod，其中 Task Board 是他們稱為「最簡單的有狀態範例」：用輸入欄新增待辦、按鈕勾選完成，資料存在外掛自己的 local store，並依工作目錄分開。操作是輸入後按 Enter 儲存，Tab 在控制項間移動，Esc 關閉 pane，Ctrl+X 再按 Tab 可把鍵盤焦點拉回 pane。他們也誠實說明：因為輸入需要鍵盤焦點，自動化測試無法穩定驅動，所以 Task Board 的原生行為只靠測試驗證、沒有親手跑過。

Sen's Sense AI 的 Todo 多了一步 suggest：讀取目前 session 的狀態，提示還有哪些事沒做，他說有兩項剛好和自己手記的待辦重合，因此把原本的待辦軟體退役了。資料層該選哪個？官方 API 表有兩個提醒：$.fs.write 不是原子操作（會就地覆寫檔案內容，其他程序可能讀到寫到一半的檔案），多個 session 都會改的資料請放 $.store。待辦、快取起算時間這類跨 session 共用的資料，用 $.store 比自己寫 JSON 檔穩。

面板 Mod 的共通注意事項

  • 讓位與疊加：先呼叫 next(e) 取得原本的畫面再疊上自己的，遇到 hasSurvey 這類官方元素就放行。
  • 拋例外會被靜默略過：OneWave AI 實測 burn meter 消失，唯一線索是 transcript 裡一行暗色文字 ui.render hook skipped: threw TypeError；每個面板 Mod 都該有測試。
  • 寬高跟著 site 走：Pane 與 band 的寬度讀 e.props.bodyColumns；dock 型 pane 的可用列數是 e.props.scroll.bodyRows。
  • 預設要自己放進 user 範圍：EP421 提醒，只在對話中產生的 Mod 只會載入那個對話，放久了還會被清掉；做完要請 Claude 搬到使用者資料夾並用 User 範圍安裝（第 4 章的安裝與管理流程）。
  • 存取範圍要寫清楚：用量儀表只需要讀 session 用量；遮罩只改畫面；待辦只寫自己的 store。能講出「這個 Mod 碰不到網路與檔案」的 Mod，才容易通過第 16 章的審查。

小結與下一章

四個案例共同的模式是「讀官方已提供的資料（用量、訊息、store），畫在 band 或 pane」，所以風險面也最小。下一章換成作者自己每天在用的四個 Mod：一個定時排入 /write-obs-log、一個監看 herdr agent、一個偵測多個 session 改同一檔案的撞車警報，以及社群的 next-steps。它們不只畫面，還會排程、跑外部指令、攔截寫入，並附上開發時踩到的坑。
