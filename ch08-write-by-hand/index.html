第 8 章 · Part 3：開發自己的 Mod

手寫一個 Mod：plugin.json、hooks.json 與 register

三個檔案、四個 hook，不需要 Node.js，也不需要 build

上一章 Claude 替你寫完了 Mod；這一章你自己動手，目的不是取代代寫，而是看懂它：之後要審查、修改或除錯任何 Mod，都得讀得懂這三個檔案。我們跟著官方 Create a mod 教學的 first-mod 走：它計算 Claude 的工具呼叫次數、把次數顯示在 spinner 旁邊，並新增一個 /tally 指令印出目前的次數。下面的 register.js 主體取自一位社群作者在 v2.1.287 上逐步實作的記錄，該文明言它依官方教學而來；其他指令與守門片段是本書依官方文件改寫或自編，會另外註明。

一個 Mod 就是三個檔案

官方 Mods reference 的 Files 一節列出一個 Mod 的組成：

檔案必要內容
.claude-plugin/plugin.json是plugin 的 manifest；Mod 沒有額外的必填欄位
hooks/hooks.json是modules：只含一個路徑的陣列，相對於這個檔案，指向 hooks module
hooks module，如 hooks/register.js是Mod 的進入點，匯出 register(on, options)；可以是 .js、.mjs、.cjs、.jsx、.ts、.mts、.cts 或 .tsx，且為 ES module
types/index.d.ts（由 manifest 的 types 指定）用到 $.state 或替 $ 新增 namespace 時才需要宣告 PluginState 的值，與 Mod 新增的 namespace
*.test.ts、*.test.tsx否claude plugin test 會執行的測試

官方也強調：不需要 Node.js、bundler 或 build 步驟，Claude Code 直接載入 .js 與 .ts。

💬

三個檔案、四個 hook，沒有 Node.js、沒有 bundler、沒有 build：寫 Mod 的門檻是讀懂它，不是建置它。

步驟一到三：manifest 與 hooks.json

先建兩層目錄，然後寫 plugin.json。依 Plugin manifest reference，name 是唯一必填鍵，建議用 kebab-case；沒有 version、description 或 author 時 validate 會給警告（加 --strict 則警告變成失敗），所以教學把它們都寫上。

bash
mkdir -p first-mod/.claude-plugin first-mod/hooks
first-mod/.claude-plugin/plugin.json
{
  "name": "first-mod",
  "version": "0.1.0",
  "description": "Counts Claude's tool calls, shows the count beside the spinner, and adds a /tally command",
  "author": { "name": "Your Name" }
}

接著是整個 Mod 最關鍵的那一行：hooks.json 的 modules。這個鍵讓一個 plugin 被當成 Mod，缺了它，這只是一個普通 plugin。

first-mod/hooks/hooks.json
{
  "description": "The first-mod hooks module",
  "modules": ["./register.js"]
}

步驟四：register.js

hooks module 匯出一個 register 函式。Mod 載入時 Claude Code 呼叫它一次，並傳入 on；每呼叫一次 on，就為一個事件註冊一個 hook。

first-mod/hooks/register.js
// The count, shared by the hooks below
let calls = 0
// Claude Code calls this once when the mod loads
export function register(on) {
  // Runs when the session starts, before your first prompt
  on('session.start', async ($, e, next) => {
    // Add the /tally command
    await $.command.register({
      name: 'tally',
      description: 'Show how many tool calls Claude has made',
    })
    // Let the session start as usual
    return next(e)
  })
  // Runs each time Claude is about to use a tool
  on('tool.call', async ($, e, next) => {
    calls += 1
    // Ask Claude Code to draw the interface again, so the new count shows
    $.ui.invalidate('ui.render')
    // Let the tool run as usual
    return next(e)
  })
  // Runs when you type /tally, and only then, because of the matcher
  on('command.run', { command: 'tally' }, async () => {
    // The text to print in the transcript
    return { text: 'Claude has made ' + calls + ' tool calls since this mod loaded' }
  })
  // Runs each time Claude Code draws the spinner
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    // Keep Claude Code's spinner, with the count added after its word
    return next({ ...e, props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' } })
  })
}

每個 hook 都收到三個一樣的參數：

  • $：mods API。Mod 要碰檔案、程序、網路或介面，都只能經過它。官方規定每個呼叫要寫完整，如 $.fs.read('notes.md')。
  • e：事件的輸入，是深度凍結的純資料；想改，要傳一份複本給 next。
  • next：下一個處理者，像 middleware：先跑後面的 hook，最後是 Claude Code 自己的行為，並回傳該事件的結果。

對照第 3 章的三種處理方式，first-mod 這四個 hook 剛好各示範一遍：

hook何時執行做什麼處理方式
session.startsession 開始（第一個 prompt 之前）與 Mod 重載時註冊 /tally觀察：回傳 next(e)，session 照常開始
tool.callClaude 要使用工具之前calls 加一，要求重畫介面觀察：回傳 next(e)，工具照常執行
command.run輸入 /tally 時（matcher 限縮為 command: 'tally'）回傳含次數的文字回答：不呼叫 next，直接回傳自己的結果
ui.render畫 spinner 時（matcher 為 Spinner 元件）在 spinner 的字後面加上次數改寫：把修改過 suffix 的 e 傳給 next

on 的第二個參數是 matcher：事件欄位的過濾條件，可以是值、允許值的陣列或正規表達式。沒有 matcher 的 hook 對該事件全部觸發。

ℹ️
module 變數會在每次重載時歸零

Claude Code 會監看用 --plugin-dir 載入的目錄，檔案一變就熱重載 hooks module；每次重載都重跑 register，所以 calls 會回到 0。要跨重載保留的值，要放進 $.state（整個 session 有效）或 $.store（跨 session），這是第 9 章的主題。

步驟五：用 validate 看 Claude Code 怎麼讀你的 Mod

claude plugin validate 檢查 manifest，並對 hooks module 的原始碼做和載入時相同的靜態分析，不會執行你的程式碼：

bash
claude plugin validate ./first-mod

# 輸出（節錄自社群作者在 2.1.287 的實測）
#   ❯ ./register.js hooks: session.start, tool.call, command.run{command=tally},
# ui.render{component=Spinner}
#   ❯ ./register.js calls: $.command.register, $.ui.invalidate
# ✔ Validation passed

驗證重點是：hooks: 列出事件（matcher 用大括號表示）、calls: 列出呼叫的 mods API，最後出現 Validation passed。靜態分析有幾項主要限制，違反會導致驗證失敗，以下整理四項：

  • 每個 mods API 呼叫要寫完整，不能把 $.ui 指派給變數，也不能解構。
  • 事件名稱要用字串常值，變數或迴圈都不行。
  • 檔案開頭用 ES module 的 import，動態 import() 不行，不要用 require。
  • 只能以相對路徑 import 自己的檔案；唯一允許的裸 import 是 claude-code（型別與少數 helper）。

這就是 Mod 沒有 Node 也沒有 DOM 的原因：限制越多，Claude Code 才能在執行前列出一個 Mod 碰了什麼。同樣的指令也是你審查別人的 Mod 的入口（第 6 章）。

💬

Mod 沒有 Node 也沒有 DOM，不是缺陷而是交換：限制越多，Claude Code 越能在執行前說清楚這個 Mod 碰了什麼。

型別宣告：Claude Code 會替你寫

用 --plugin-dir 在互動 session 載入 Mod 時，Claude Code 會把 TypeScript 宣告檔寫進 Mod 的 .claude-plugin/types/。其中 claude-code/index.d.ts 涵蓋你這個版本的每個事件與其輸入、輸出、每個 mods API namespace 與方法，並為每個方法附上註解與範例；claude-code-tools/index.d.ts 宣告內建工具的輸入與結果，讓 e.tool === 'Bash' 這類判斷能縮小型別。Mod 沒有自己的 tsconfig.json 時，Claude Code 也會補一份，編輯器與 tsc -p ./first-mod 都能直接用。官方的建議是：事件與方法會隨版本變動，檔案與網頁說法不一致時，以這些宣告檔為準。

步驟六、七：載入並實際跑

不安裝，只在單一 session 載入：

bash
# 非互動模式：只驗證 session.start 與 command.run 兩個 hook
claude -p "/tally" --plugin-dir ./first-mod --max-turns 1
# first-mod: Claude has made 0 tool calls since this mod loaded

# 互動模式：spinner 與 tool.call 在這裡才看得到
claude --plugin-dir ./first-mod

-p 模式沒有互動畫面，只有 session.start 與 command.run 會被觸發，所以輸出是 0 次工具呼叫；--max-turns 1 是那位作者自己加的，官方教學沒有加也得到相同的輸出。進入互動模式後，執行 /plugin，分頁下方會有一行 1 mod active · first-mod；請 Claude 列出檔案、讀一個檔案，spinner 後面會出現 tool calls: N，結束後輸入 /tally 就會看到總數。

⚠️
兩個容易踩的環境問題

一是版本：多位日本作者因為 Homebrew 舊版 CLI（2.1.226、2.1.234）和 Desktop 內附的 2.1.286 並存，遇到莫名的 validate 錯誤，建議每個使用的地方各查一次版本。二是顯示位置：Mod 畫的介面只出現在終端機與 Desktop 的 Code 分頁；VS Code 擴充套件的對話面板裡 hook 仍會執行，但看不到介面，我自己實測也是如此。

要擋東西的 Mod：加上 .catch

如果你的 Mod 是守門員（拒絕工具呼叫），多一個必要的寫法。on 會回傳一個註冊物件，它有一個方法 .catch(handler)，用來設定 hook 的錯誤處理。原因是：一個丟出例外、或超過 10 秒時限的 hook 會被略過，被略過的守門 hook 等於放行。社群教學 safe-shell 範例的 fail closed 寫法如下（這裡只留骨架），next.called 只在 .catch 處理函式裡可用，true 代表該 hook 出錯前已經呼叫過 next：

register.js（片段）
export function register(on) {
  on('tool.call', { tool: 'Bash' }, ($, e, next) => {
    // ...判斷這個指令能不能跑...
    return next(e)
  }).catch(($, e, next) =>
    // 守門的 hook 自己壞掉時要拒絕，而不是放行
    next.called ? next(e) : { deny: 'the guard failed, so the command was not run.' },
  )
}

驗證時 validate 會為每個可能拒絕動作的 hook 多印一行，標出它有沒有 .catch，審查別人的守門 Mod 時先看這一行。守門 Mod 的完整範例留到第 12 章。

💬

守門 hook 被略過就等於放行，所以它自己壞掉時，要拒絕得親手用 .catch 寫出來。

小結

  • Mod = plugin.json + hooks/hooks.json（modules 一行）+ 匯出 register(on) 的 hooks module。
  • hook 收到 $、e、next：回 next(e) 是觀察，傳修改過的複本是改寫，不呼叫 next 是回答。
  • 先 validate，再用 --plugin-dir 載入實測；要求失敗時拒絕的守門 hook，要加 .catch。
