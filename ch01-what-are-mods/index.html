第 1 章 · Part 1：認識 Mods

什麼是 Claude Mods：在 Claude Code 裡面跑的外掛

Mods 的定義、定位與存在的意義

Claude Code 本來改不動的東西

用過 Claude Code 一陣子的人，多半已經做過不少客製：用 settings.json 調權限、用 CLAUDE.md 留下長期指示、用 hooks 在工具執行前後跑腳本、接 MCP 伺服器、設狀態列與輸出風格。The New Stack 的報導把這些手段的上限講得很清楚：它們能影響 Claude 遵守的指示、權限與可用的工具，但改不了 Claude Code 自己的功能，也改不了介面的其餘部分。

2026 年 10 月 1 日，隨 Claude Code 2.1.287 上線的 Mods 補的就是這一塊。Claude Code 的創作者 Boris Cherny 在 X 上的說法是：「Each person works differently, so there's no reason why everyone should have an identical Claude experience.」

💬

hooks、skills、MCP 管得到 Claude 該遵守什麼、能用什麼；Mods 才管得到 Claude Code 自己長什麼樣子、怎麼動。

Mod 的定義

官方文件的定義很短：Mod 是一個會改變 Claude Code 外觀與行為的 plugin，由 JavaScript 或 TypeScript 的事件處理函式組成。事件發生時，例如一次 tool call、一則送出的 prompt、或介面某一塊即將繪製，Claude Code 就呼叫對應的函式，函式可以觀察事件、改寫事件，或是整個接管。

這裡先釘住兩個後面會一直出現的用詞，全書沿用：

  • hook：在本書談到 Mod 時，指 Mod 的事件處理函式。這是官方文件的用法。
  • settings hook：寫在設定檔裡、以 shell 指令、HTTP 請求或 prompt 等形式執行的既有 hooks。官方把兩者都叫 hooks，所以文件刻意用「settings hook」來區分。

兩者的關鍵差異是執行位置：settings hook 在 Claude Code 外面跑，Mod 的 hook 是在 Claude Code 程序裡面執行的函式。這個差別決定了 Mod 能做什麼，下一節會看到。

Mod 能做的五件事

因為跑在 Claude Code 內部，官方列出 Mod 能做、其他機制做不到的事：

  • 繪製可操作的介面：在對話記錄旁開窗格（pane），或在輸入框上方放一條橫帶（band），裡面可以有分頁、按鈕與文字輸入框。
  • 重繪 Claude Code 自己畫的部分：取代或改樣式的對象包括 tool call 那一列、spinner，以及 Claude 向你提問的對話框。
  • 介入 tool call 或請求：例如在詢問你之前先扣住一個 tool call、不執行工具就直接回答，或把某次請求改送給別的模型。
  • 用指令直接執行你的程式：新增一個 /command，立刻執行你的函式，不經過 Claude 的回合，Claude 正在工作時也能用。
  • 在 hook 之間共享資料：同一個 Mod 的 hook 共用檔案裡的變數，一個 hook 記錄的東西，另一個 hook 可以拿來顯示。

一個典型的用途，官方文件舉的是「每次請求後畫出 context 用了多滿的窗格」。這件事 skill 做不到（skill 只給 Claude 文字），MCP 伺服器做不到（它只給 Claude 工具），settings hook 也做不到（它不能在介面上畫東西）。

💬

skill 給文字、MCP 給工具、settings hook 管事件放不放行；能把 context 用了多滿畫在畫面上的，只有 Mod。

最小的 Mod 長什麼樣子

一個小 Mod 只要三個檔案：

first-mod/
first-mod/
├── .claude-plugin/
│   └── plugin.json
└── hooks/
    ├── hooks.json
    └── register.js
  • plugin.json：plugin 的清單（manifest）。
  • hooks.json：指向你的程式碼檔案。
  • register.js：你的程式碼，稱為 hooks module，負責告訴 Claude Code 要在哪些事件上執行哪些函式。

下面是官方 Mods overview 的完整 register.js。它計算 Claude 呼叫工具的次數，並在 Claude 工作時把次數顯示在 spinner 旁，畫面會像 Thinking · tool calls: 3…：

hooks/register.js
// The count, shared by the two hooks below
let calls = 0

// Claude Code calls this once when the mod loads
export function register(on) {
  // Runs each time Claude is about to use a tool
  on('tool.call', async ($, e, next) => {
    calls += 1
    // Ask Claude Code to draw the interface again, so the new count shows
    $.ui.invalidate('ui.render')
    // Let the tool run as usual
    return next(e)
  })

  // Runs each time Claude Code draws the spinner
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    // Keep Claude Code's spinner, with the count added after its word
    return next({ ...e, props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' } })
  })
}

這個檔案註冊了兩個 hook，它們共用最上面的 calls 變數：

  • tool.call hook 在 Claude 每次要使用工具前執行：把 calls 加一、要求 Claude Code 重畫介面，然後用 next(e) 讓工具照常執行。
  • ui.render hook 在 Claude Code 每次繪製 spinner 時執行：保留原本的 spinner，只在文字後面接上次數。第二個參數 { component: 'Spinner' } 是篩選條件，沒有它，這個 hook 會對每一個繪製事件都執行。

兩個 hook 其實示範了不同的處理方式：第一個只是觀察事件，記一筆就放行；第二個改寫事件，把改過的副本傳給 next。還有第三種「接管」：不呼叫 next，直接自己回答，原本的行為就不會發生，例如拒絕一個指令。第三章會把這三種處理方式、$、e、next 三個參數與事件清單一次講完整，這一章只需要建立一個印象：Mod 就是一組掛在事件上的函式。

💬

觀察是記一筆就放行，改寫是遞一份改過的副本，接管是不呼叫 next：三種處理方式，差別只在你怎麼對待 next。

從 Function Hooks 到 Mods：它是怎麼來的

如果你在 2026 年 9 月看過相關討論，可能記得的是另一個名字。以下時間線出自 The New Stack 與影片整理；9 月的兩個日期我沒有找到官方原文可核實，10 月 1 日與 2.1.287 則有官方文件支持：9 月 3 日，Anthropic 在 GitHub 的 anthropics/claude-code repo 提出 issue，以比較技術性的名稱「function hooks」徵求回饋，想做的是讓 JavaScript 與 TypeScript 函式攔截 Claude Code 內部事件的 API；9 月 9 日，官方表示即將推出，產品名定為 Claude Mods，function hooks 則保留作為底層機制的稱呼；10 月 1 日，Mods 隨 2.1.287 正式上線，預設開啟。

ℹ️
預覽期的舊說明要小心

預覽期間需要設定環境變數 CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 才能啟用。官方文件現在的說法是：如果你在 early access 期間設過它，請移除；2.1.287 以後的版本會忽略這個變數，設成 0 也關不掉 Mods。網路上仍有不少文章停留在預覽期的寫法，包括把它描述成尚未正式推出的實驗功能，遇到時以官方文件為準。

要用哪個版本、在哪裡跑

Mods 預設開啟。終端機需要 Claude Code v2.1.287 以上，可用 claude --version 確認；Desktop app 內建自己的 Claude Code，從 v2.1.286 起就支援 Mods。

執行位置要分兩層看：Mod 的 hook 在載入該 plugin 的各種 session 裡都會執行，但「畫出來的東西」只有終端機（包含編輯器內建終端機與 JetBrains plugin）和 Desktop app 的 Code 分頁看得到。在 VS Code 擴充套件的聊天面板、claude -p、Agent SDK 與雲端 session 裡，hook 照跑，但介面不會出現。Desktop app 的 WSL session 則完全不載入 Mods，因為那裡沒有 plugin。完整的對照表留到第三章。

有些內建功能本身就是 Mod

Anthropic 自己也用 Mods 做功能。在 Claude Code 裡輸入 /plugin，到 Installed 分頁，Built-in 底下就列著內建的 Mod，例如接管 /diff 並繪製其窗格的 cc-plugin-diff，以及把 AGENTS.md 載入成專案指示的 cc-plugin-agents-md。其中 diff、agents-md、sec-default、telemetry 的原始碼公開在 Claude Code repo 的 mods 目錄，是學習寫法的現成教材。第五章會逐一拆解。

取得 Mod 的三條路

官方把入口整理成三種：用現成的（例如內建的 /diff）、自己做（在 session 裡描述需求，由 Claude 代寫；或照教學手寫）、以及從 marketplace 安裝。安裝的指令格式是 plugin 名稱、@、marketplace 名稱，官方範例如下：

bash
# 在 Claude Code session 裡
/plugin install token-chart@your-org

# 或在 shell 裡
claude plugin install token-chart@your-org

Mod 是以 plugin 的形式發行與安裝的，所以 marketplace、安裝範圍與更新方式都和一般 plugin 相同；詳細流程是第四章的主題。Anthropic 另外在 claude-code-playground repo 的 claude-code/mods 目錄放了幾個範例 Mod，例如在輸入框上方畫出 context 預報的 token-weather，以及扣住 rm -rf、force push 等高風險指令並顯示影響範圍的 blast-radius，官方註明這些範例「照原樣分享，不提供支援」。

⚠️
先記住一件事：Mod 沒有沙箱

官方文件的原話是，Mod 是以你的權限執行的程式碼，可以讀寫檔案、啟動程序與發出網路請求，所以只該安裝來自你信任的作者與 marketplace 的 Mod。這一點會在第十五章詳細談；這裡先留下一個習慣：安裝前先用 claude plugin validate 看它掛了哪些事件、呼叫了哪些 API，第四章會示範。

💡
別和同名的社群專案搞混

GitHub 上有一個獨立的社群 repo 叫 0xDarkMatter/claude-mods，是 skills 與 agents 的工具集，和 Anthropic 這次推出的原生 Mods 功能無關。本書談的一律是後者。

小結

Mod 是跑在 Claude Code 程序內部的 plugin：用 JavaScript 或 TypeScript 寫事件處理函式，能觀察、改寫或接管事件，能在介面上畫東西，還能新增立刻執行的指令。它不取代 hooks、skills、MCP，而是補上它們共同做不到的那一塊：改變 Claude Code 自己的介面與行為。

下一章要回答一個實際的問題：Claude Code 已經有 hooks、skills、plugins 與 MCP，什麼情況才值得用 Mod？我們會逐項對照它們的分工，並整理出一套「先用最輕的工具」的選擇順序。
