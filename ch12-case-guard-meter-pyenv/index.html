守門器、輪次計量條與 /pyenv

三個實戰案例：守門、計量條與 /pyenv

前面幾章講的是零件。這一章用三個完整的案例把它們組起來：一個擋下危險操作的守門器、一個畫在輸入框上方的輪次計量條、一個替 Claude 查 Python 環境的 /pyenv。三個案例的程式碼都取自 Kanaries 的教學文章，作者在 Claude Code 2.1.293 的 Desktop app 上實作，三個 mod 都通過 claude plugin validate 與共 8 個自動化測試。程式碼我逐字保留，包含英文註解。

案例一：守門器 safe-shell

目標很單純：Claude 在自動模式或繞過權限的模式下，沒有東西會在 git reset --hard 之前攔住它。這個 mod 拒絕三種 shell 指令，並且不讓 .env 檔進入對話。

safe-shell/hooks/register.ts
import type { Register } from 'claude-code'

// Shell commands an agent should never run without a human typing them.
const BLOCKED: { pattern: RegExp; reason: string }[] = [
  {
    pattern: /\brm\s+-[a-zA-Z]*[rR][a-zA-Z]*\s+(\/|~|\$HOME)\/?\*?(\s|$)/,
    reason: 'recursive delete of / or the home folder',
  },
  {
    pattern: /\bgit\s+push\b.*(--force\b|--force-with-lease\b|\s-f\b).*\b(main|master)\b/,
    reason: 'force push to main or master',
  },
  {
    pattern: /\bgit\s+reset\s+--hard\b/,
    reason: 'git reset --hard throws away uncommitted work',
  },
]

// .env, .env.local, config/.env.production ... but not .env.example.
const isSecretEnvFile = (path: string) =>
  /(^|\/)\.env(\.[^/]+)?$/.test(path) && !/\.(example|sample|template)$/.test(path)

export const register: Register = on => {
  on('tool.call', { tool: 'Bash' }, ($, e, next) => {
    const hit = BLOCKED.find(rule => rule.pattern.test(e.command))
    if (hit === undefined) {
      return next(e)
    }
    $.ui.toast(`safe-shell blocked: ${hit.reason}`)

    return { deny: `safe-shell: blocked (${hit.reason}). Ask the user to run it themselves.` }
  }).catch(($, e, next) =>
    // Fail closed: if the guard itself breaks, refuse instead of letting the command through.
    next.called ? next(e) : { deny: 'safe-shell: the guard failed, so the command was not run.' },
  )

  for (const tool of ['Read', 'Edit', 'Write'] as const) {
    on('tool.call', { tool }, ($, e, next) =>
      isSecretEnvFile(e.file_path)
        ? { deny: `safe-shell: ${e.file_path} holds secrets and stays out of the conversation.` }
        : next(e),
    ).catch(($, e, next) =>
      next.called ? next(e) : { deny: 'safe-shell: the guard failed, so the file was not touched.' },
    )
  }
}

先把規則讀清楚。第一條擋下對 /、~ 或 $HOME 的遞迴刪除；第二條只擋強制推送到 main 或 master，--force、--force-with-lease 與 -f 都算；第三條擋 git reset --hard。isSecretEnvFile 認得 .env、.env.local 與 config/.env.production，但放行 .env.example 這類範本檔，所以 Read、Edit、Write 三個工具用同一個迴圈各掛一個 hook，被拒絕時 Claude 讀到的是 deny 的文字，使用者另外會看到一個 toast。

有兩個設計比正規表示式更重要。第一，守門器在呼叫 next 之前就決定，因為 next 一旦執行，指令就已經跑了，之後回 deny 也無法復原。第二，每個守門 hook 都接 .catch，讓它「失敗就拒絕」：hook 丟例外或超過 10 秒時預設會被跳過，守門器被跳過就是放行，next.called ? next(e) : deny 這個 handler 改成拒絕。第 11 章解釋過 next.called 的意義。

驗證時要看的第一件事，是每個守門 hook 有沒有 .catch：

claude plugin validate 的輸出
❯ ./register.ts hooks: tool.call{tool=Bash}, tool.call{tool=Read|Edit|Write}
❯ ./register.ts gating hook with .catch: tool.call{tool=Bash}
❯ ./register.ts gating hook with .catch: tool.call{tool=Read|Edit|Write}
❯ ./register.ts calls: $.ui.toast
✔ Validation passed

測試時，守門器在 next 之後沒有人回答，所以要先註冊 stand-in。作者的第一次執行就因為順序錯誤失敗，原因與第 10 章提過的一樣：stand-in 要在第一個 $ 呼叫之前註冊。

守門器的測試（節錄）
import { expect, test } from 'claude-code/testing'

const ran = { stdout: 'ran', stderr: '', interrupted: false }

test('blocks rm -rf on the home folder', async ($, on) => {
  on('tool.call', { tool: 'Bash' }, () => ({ result: ran }))
  const answer = await $.tool.call({ tool: 'Bash', command: 'rm -rf ~' })
  expect(answer.deny).toContain('recursive delete')
})

test('lets ordinary commands through', async ($, on) => {
  on('tool.call', { tool: 'Bash' }, () => ({ result: ran }))
  const answer = await $.tool.call({ tool: 'Bash', command: 'rm -rf ./build && python -m pytest -q' })
  expect(answer.deny).toBeUndefined()
})

作者實測時，叫 Claude 執行 echo "the words git reset --hard inside an echo"，守門器照樣擋下：比對文字分不出「指令」與「提到指令的文字」，也抓不到藏在變數、腳本或別名裡的指令。真正不能發生的事，應該寫進權限的 deny 規則，而且不要只靠單一層。官方文件說，內建守門器載入時，使用者的 mod 不能核准被 deny 規則拒絕的呼叫，但管理員若設了 allowModsToOverrideDenyRules，這個保證就不成立；守門器沒有載入的地方，這個保證也不適用。

案例二：輪次計量條

輸入框上方的色帶與側邊面板是 mod 畫得最多的地方：在作者引用的 10 月 6 日目錄掃描裡，41% 的 mod 畫在色帶、40% 開面板。這個計量條顯示上一輪的耗時、工具呼叫次數與 token 數，還有一個 Hide 按鈕。畫面讀的值放在 $.state，而且每一個值都要在型別檔宣告，否則驗證不過：

types/index.d.ts
// types/index.d.ts, named in plugin.json as "types": "./types/index.d.ts"
export type TurnStats = {
  seconds: number
  tools: number
  inputTokens: number
  outputTokens: number
  model: string | null
}

declare module 'claude-code' {
  interface PluginState {
    'turn-meter': { last: TurnStats | null; isHidden: boolean }
  }
}

hook 本身負責四件事：prompt.submit 把計數歸零、tool.call 數主對話的工具呼叫（子代理的呼叫帶 agentId，要排除）、turn.complete 從 durationMs 與 usage 算出這一輪的數字並寫入 state，最後 ui.render 畫色帶：

turn-meter/hooks/register.tsx
import { atom, read, update } from 'claude-code'
import type { Register } from 'claude-code'

import type { TurnStats } from '../types'

const last = atom({ plugin: 'turn-meter', key: 'last' } as const, null)
const isHidden = atom({ plugin: 'turn-meter', key: 'isHidden' } as const, false)

const formatTokens = (n: number) => (n >= 1000 ? `${(n / 1000).toFixed(1)}k` : String(n))

export const register: Register = on => {
  let tools = 0

  on('prompt.submit', ($, e, next) => {
    tools = 0
    return next(e)
  })

  on('tool.call', ($, e, next) => {
    // Count the main conversation's calls; subagents carry an agentId.
    if (e.agentId === undefined) tools += 1
    return next(e)
  })

  on('turn.complete', async ($, e, next) => {
    if (e.agentId !== undefined) return next(e)
    const usage = e.usage
    const stats: TurnStats = {
      seconds: Math.round(e.durationMs / 1000),
      tools,
      inputTokens: usage
        ? usage.input_tokens + usage.cache_read_input_tokens + usage.cache_creation_input_tokens
        : 0,
      outputTokens: usage?.output_tokens ?? 0,
      model: usage?.model ?? null,
    }
    await update($, last, () => stats)
    if (stats.seconds > 120) $.ui.toast(`That turn took ${stats.seconds}s`)
    return next(e)
  })

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const stats = await read($, last)
    if (e.props.hasSurvey || stats === null || (await read($, isHidden))) return next(e)

    const { Box, Button, Text } = $.ui.resolve(e)
    const model = stats.model === null ? '' : ` · ${stats.model}`
    // The band is shared by every mod: keep what the mods beneath drew, then add a row.
    const below = await next(e)

    return (
      <Box flexDirection="column">
        {below}
        <Box>
          <Text dimColor>
            {`Last turn: ${stats.seconds}s · ${stats.tools} tool calls · ${formatTokens(stats.inputTokens)} in / ${formatTokens(stats.outputTokens)} out${model} `}
          </Text>
          <Button key="hide" label="Hide" onPress={() => update($, isHidden, () => true)} />
        </Box>
      </Box>
    )
  })
}

幾個細節值得留意：輸入 token 是 input_tokens、cache_read_input_tokens 與 cache_creation_input_tokens 三者相加，所以數字反映整輪實際送進模型的量；一輪超過 120 秒會額外跳 toast；hasSurvey 為真、還沒有任何一輪的資料、或使用者已按 Hide 時，hook 直接回 next(e) 把位置還回去。Hide 按鈕的 onPress 寫的是 state 而不是模組變數，所以按下去之後畫面會自己重畫，不必另外呼叫 $.ui.invalidate。

💬

在 10 月 6 日的目錄掃描裡，41% 的 mod 畫在色帶、40% 開面板：輸入框上方這一條，是 mod 畫得最多的地方。

在作者的測試裡，終端機與桌面版都畫出這一行：

桌面版與終端機畫出的色帶
Last turn: 42s · 0 tool calls · 18.2k in / 800 out · claude-opus-5-5 [ Hide ]

作者從這個案例學到三件事。一，畫面用的值放 $.state 而不是模組變數，熱重載會重新執行 register 讓變數歸零，$.state 則會留著；/clear 會重來，要跨 /clear 保留就在 session.end 寫進 $.store。二，色帶是共用的：要先 await next(e)，把結果放進自己的 Box，否則會蓋掉其他 mod 的那一行，有位 note.com 的作者就因此弄丟過一條色帶。三，Text 元素沒有 key，測試時要用它的文字去找，像 ui.find({ type: 'Text', text: /Last turn/ })。

案例三：/pyenv

資料科學的場景有個常見問題：Claude 的 Bash 工具執行的是 PATH 上第一個 python3，那常常不是你專案的環境。/pyenv 在 session 的 shell 環境執行一段探測，結果分成兩份：text 是你看到的那一行，context 是只有模型讀得到的備註，讓 Claude 之後的 Bash 呼叫知道用的是哪個直譯器，不必你再多說一句。

💬

作者掃描的 2,690 個公開 mod，名稱或描述提到 Jupyter、pandas、venv 或 conda 的一個也沒有；而 Claude 的 Bash 跑的，偏偏是 PATH 上第一個 python3。

探測腳本讀的是套件的 metadata 而不是真的 import，所以不論 pandas 有多肥都很快；它依序回報直譯器路徑與版本、目前啟用的 VIRTUAL_ENV 或 CONDA_PREFIX，以及五個資料科學常用套件有沒有安裝。作者在 2026 年 10 月 6 日掃描的 2,690 個公開 mod 裡，名稱或描述提到 Jupyter、pandas、DataFrame、Polars、venv 或 conda 的一個也沒有，這個小工具填的是這個空缺。

pyenv/hooks/register.ts
import type { Register } from 'claude-code'

// Reads package versions from metadata instead of importing them, so it stays fast.
const PROBE = `
import os, sys
from importlib.metadata import PackageNotFoundError, version
env = os.environ.get("VIRTUAL_ENV") or os.environ.get("CONDA_PREFIX") or "none (system or tool-managed Python)"
print(f"python: {sys.executable} ({sys.version.split()[0]})")
print(f"env: {env}")
for name in ("pandas", "numpy", "polars", "matplotlib", "pygwalker"):
    try:
        print(f"{name}: {version(name)}")
    except PackageNotFoundError:
        print(f"{name}: not installed")
`

export const register: Register = on => {
  on('session.start', async ($, e, next) => {
    await $.command.register({
      name: 'pyenv',
      description: "Show which Python, environment and data packages this session's shell uses",
    })
    return next(e)
  })

  on('command.run', { command: 'pyenv' }, async $ => {
    try {
      const probe = await $.process.run(['python3', '-c', PROBE], { timeoutMs: 15_000 })
      if (probe.exitCode !== 0) {
        return { text: `pyenv: python3 exited with ${probe.exitCode}: ${probe.stderr.trim().slice(0, 300)}` }
      }
      const report = probe.stdout.trim()
      // `text` is the row you see; `context` is a note only the model reads.
      return {
        text: report,
        context: [`Python environment of this session's shell, from /pyenv:\n${report}`],
      }
    } catch (error) {
      return { text: `pyenv: could not run python3 (${String(error).slice(0, 200)})` }
    }
  })
}

python: /Users/<you>/.local/bin/python3 (3.14.2)
env: none (system or tool-managed Python)
pandas: 3.0.1
numpy: 2.4.2
polars: not installed

這份輸出顯示當時沒有啟用虛擬環境，所以 Claude 的 pip install 會裝進全域的直譯器。mod 的指令直接執行你的函式，不花一輪模型。要讓它在 Claude 工作中也能執行，登記時得加 immediate: true（教學原文說指令在 Claude 忙碌時也會立即執行，官方 API 文件則要求這個旗標，以官方為準）。$.process.run 收的是參數陣列、不經 shell，預設 30 秒逾時，這裡明確設成 timeoutMs: 15_000。作者另外確認過 PATH：在他的 Desktop session 裡，單純的 $.process.run 拿到的 PATH 與 Bash 工具完全一樣；改用 zsh -lc 登入 shell 反而讀不到 ~/.zshrc，解析到錯的版本。所以維持單純呼叫，結果看起來不對時，用在提示字元輸入 !which python3 比對。測試時，替 $.process.run 與 $.command.register 這類 $ 呼叫做 stand-in，要回 { value: ... }。

它也有明確的邊界：如果你的分析主要在 notebook 裡做，這個 mod 幫助有限，因為 Claude Code 是把 .ipynb 當 JSON 檔編輯，看不到執行中的 kernel。

三個案例的對照

三個 mod 各代表一種常見的形狀：守門器介入事件、計量條畫在畫面上、/pyenv 回應使用者的指令。挑哪一種做起點，取決於你要改變 Claude 做的事、要看見 Claude 做了什麼，還是要在需要時隨手問它一件事。差別主要在失敗時要怎麼收場：

案例核心事件使用的 $ API失敗時的選擇
守門器tool.call$.ui.toast拒絕（.catch 回 deny）
計量條turn.complete、ui.render$.state、$.ui.resolve、$.ui.toast放行（只負責顯示）
/pyenvsession.start、command.run$.command.register、$.process.run回一行錯誤文字，不丟例外
