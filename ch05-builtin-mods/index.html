第 5 章 · Part 2：安裝與使用

內建 Mods：sec-default、diff、telemetry 與 agents-md

先看 Claude Code 自己已經裝好的四個 Mod，再決定要不要自己加

前一章你學會了安裝與管理第三方 Mod。但在你裝任何東西之前，Claude Code 裡其實已經有 Mod 在跑：/diff 的面板、AGENTS.md 的載入、分析事件的上傳，都是用同一套機制寫成的。官方把這些內建 Mod 的原始碼公開在 anthropics/claude-code 的 mods/ 目錄，它們也是最可靠的範本：讀它們，你看到的就是官方自己怎麼用 hooks module、$ 與事件。

💬

最可靠的 Mod 教材，早就裝在你的 Claude Code 裡了：內建 Mod 與你寫的 Mod 走同一套機制，原始碼就公開在 mods/。

先認識內建 Mod 的共同特性

官方 Mods overview 的說明是：想看目前 session 有哪些內建 Mod，在提示符輸入 /plugin，切到 Installed 分頁，它們列在 Built-in 底下。內建 Mod 不能更新、也不能解除安裝；每一個各有自己的關閉方式。另外，前面章節提到的「mods active」那一行不會列出內建 Mod。

/plugin 顯示的名稱作用怎麼關
cc-plugin-sec-default保護組織管理的內容，不被使用者安裝的 Mod 動到使用者不能關；由管理員在 managed settings 決定順序
cc-plugin-diff接管 /diff 並畫出面板（互動式終端機 session）在 /plugin 停用；/diff 仍在，改由內建版本回應
cc-plugin-telemetry送出 Claude Code 與內建 Mod 記錄的分析資料在 /plugin 停用，或關掉分析，例如 DISABLE_TELEMETRY
cc-plugin-agents-md把 AGENTS.md 當成專案指令載入在 /plugin 停用，或選擇要載入哪些指令檔

表格出自官方 Mods overview。同一份表格還有第五列 cc-plugin-plugin-authoring（只放一個 plugin-authoring skill，沒有 Mod 程式碼，第 7 章會用到）與預設停用的 cc-plugin-you-should-know，本章不展開。

⚠️
停用 hooks 的開關擋不住內建 Mod

官方明說：disableAllHooks、--bare、--safe-mode 這類會停掉「已安裝 Mod」的設定與旗標，不會停掉內建 Mod。想關內建 Mod，只能走上表最後一欄的方式。

sec-default：為組織守住政策

sec-default 是四個之中最特別的一個：它不為使用者增加任何功能，只做防守。要理解它，先記得一件事：hooks 鏈上有分層。使用者自己裝的 Mod 在 user 層，組織可以在它前面（prepend）與後面（append）各放自己的 Mod。sec-default 被放在最外側，README 把它的動作歸納為三招：越過 user 層繼續往下傳（next.to(e, "append")）、依名稱拒絕 user 層的呼叫者（{ deny } 或 { refuse }）、或原樣放行（next(e)）。

它保護的是函式式 hooks 出現以前，使用者碰不到、但現在碰得到的東西：組織的 classic hooks、managed CLAUDE.md 與 rules、settings 的讀取、MCP 白名單、tool.check 上生效的 deny 規則，以及被 managed env 釘住的環境變數。官方管理員文件的白話版是：使用者的 Mod 不能改動你的 managed hooks 收到或決定的內容、系統提示、managed 指令檔、任何 Mod 讀到的設定，或你的 managed MCP server 的工具與說明。

💬

sec-default 不替使用者加功能；它守住組織的 managed hooks、指令檔與設定，也不讓 user 層 Mod 放寬受保護的 deny 規則。

什麼時候它會載入

官方文件列了兩個條件，符合任一個就載入：機器上有 managed settings；或使用者以 Team、Enterprise 方案登入。用 API key，或透過 Bedrock、Google Cloud 的 Agent Platform、Foundry 的使用者，只有在機器上有 managed settings 時才會有這道守衛。

兩個管理員選項

README 列出兩個選項，都只讀 managed settings（使用者、專案、本機設定檔或 --settings 裡寫了同樣的鍵，完全不算）。第一個 allowManagedModsOnly：只有組織透過 managed settings 部署的 Mod 與內建 Mod 能載入，使用者裝的、用 --plugin-dir 指定的、放在自己 mods 資料夾的，一律拒絕。官方文件特別補了一句，連 Claude 在 session 裡代寫的 Mod 也算在內。

managed-settings.json
{
  "pluginConfigs": {
    "cc-plugin-sec-default@builtin": {
      "options": {
        "allowManagedModsOnly": true
      }
    }
  }
}

第二個 allowModsToOverrideDenyRules 預設關閉，且只有字面上的 true 才算數。為什麼要有這個？因為在 tool.check 上任何 hook 都能回答任何判決，一個「幫你省掉權限提示」的 Mod（回傳 decision: "allow"）連 deny 規則也一起放行了。sec-default 在位時會再跑一次不含 user 層的鏈，如果 user 層把判決放寬了，就以較嚴格的那次為準；README 把這段稱為「Deny rules hold」。細節以 README 為準：受保護的不只 deny，還包括有來源（settings 規則、傳統 hook、組織上限）的 ask，沒有指名來源的 ask 則不受保護。

ℹ️
它有成本，也有盲區

README 自己寫明：因為它 hook 了 tool.check，每一次工具呼叫都會跑這條鏈；hook ui.log、env.get、env.set 也各增加一條要跑的鏈。盲區方面，被擋下來的 ask 仍然是 ask，使用者的 classic PermissionRequest hook 還是能回答它，那要靠 allowManagedHooksOnly 去管。完整的取捨留到第 15、16 章討論。

diff：用 Mod 重畫的 /diff 面板

diff 是最適合初學者讀的內建 Mod，因為它做的事你每天都看得到：/diff 在 transcript 旁開出面板，列出 session 的未提交變更，每個檔案一列、下方是 hunks，每次開關都會在 transcript 留下 Diff panel shown 或 Diff panel hidden。Claude 改檔案或跑 shell 指令時面板會自動更新；session 裡第一次成功編輯時，在版面與寬度允許的情況下面板會自己打開。

它的比較基準可以選：對 session 開始時的狀態、對 HEAD，或對與預設分支的 merge-base；選擇依 repository 存在 Mod 自己的 store。非 git repository 時 /diff 只會告訴你這件事，什麼也不做。

從 README 的 hooks 表可以看到一個 Mod 通常由哪些事件組成：session.start 註冊 /diff、ui.render 畫面板、command.run 處理指令、ui.scroll 與 ui.focus 處理互動、tool.call 在 Edit、Write、Bash 之後重新整理。想看原始碼運作，可以直接載入並測試：

bash
# 從原始碼讀 diff 這個 Mod，載入一個 session
claude --plugin-dir mods/diff

# 跑它自己的測試
claude plugin test mods/diff

停用 diff 之後，/diff 不會消失，而是退回內建版本。也就是說，引擎自己仍保有一份 /diff 的實作。

telemetry：只服務內建 Mod 的分析通道

telemetry 的角色很容易誤會。它不是讓你的 Mod 回報資料的管道：它加進 $ 的 $.telemetry 有兩個事件 log 與 mark，而它最上面有一道 gate，只讓內建層的呼叫者通過，其他來源（使用者安裝的、管理員列出的）一律拒絕並附上理由。README 也明講它不是要拿來安裝或用 --plugin-dir 載入的。

送出的資料有幾條限制，都寫在 README：

  • DISABLE_TELEMETRY、CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 或 DO_NOT_TRACK 在身上時什麼都不送；測試執行、Bedrock／Vertex／Foundry 這類它不管理的第三方 provider、雲端 gateway 也是。每一批送出前都會重新讀這些開關，讀不到就不送。
  • 不接受自由文字：事件名稱與每個屬性鍵都必須是 snake_case，值只能是有限數字、布林，或是附有候選清單的 Choice 字串；違規的條目在排進佇列前就被拒絕。
  • 批次送出：第一筆排入後數秒送出、累積一百筆時立刻送、session 結束時再送；遇到伺服器錯誤、逾時或限流會重試一次，仍失敗就丟棄。

它另一個價值是示範「noun contract」：把新的名詞加進 $ 的 Mod，要把型別放在 types/index.d.ts。diff 與 agents-md 都用 $.telemetry 記錄事件，而 telemetry 不在場時，這些呼叫會被無聲丟棄、其他功能不受影響。這個設計在第 11 章會詳談。

agents-md：用一個選項決定指令檔怎麼載入

agents-md 讓 Claude Code 讀 AGENTS.md，方式與讀 CLAUDE.md 一致。它有一個選項 instructionFiles，四個值：

值行為
claude-md只載入 CLAUDE.md（引擎原本行為），Mod 什麼都不加
claude-md-or-agents-md（預設）專案沒有自己的 CLAUDE.md 時才改載 AGENTS.md
claude-md-and-agents-md兩者都載入；已被 CLAUDE.md 以 @ 匯入或連結的不重複載入
managed-only丟掉專案與個人的指令檔，只留組織的 managed CLAUDE.md 與引擎的 memory

作為內建 Mod，選項在 /config 的「Project instructions」列用選單切換；手動則寫在使用者設定（~/.claude/settings.json）、--settings 或 managed settings。README 特別說明，專案的 .claude/settings.json 不會被讀來取得 plugin 選項：

~/.claude/settings.json
{
  "pluginConfigs": {
    "agents-md@builtin": {
      "options": { "instructionFiles": "claude-md-and-agents-md" }
    }
  }
}
⚠️
兩處對插件 id 的寫法不一致

agents-md 的 README 範例設定鍵是 agents-md@builtin，官方 overview 表格顯示的名稱是 cc-plugin-agents-md（那是顯示名稱，不要由它推導設定鍵），sec-default 的設定鍵則明確是 cc-plugin-sec-default@builtin。依官方文件的說法，名稱以 /plugin 實際顯示為準；如果設定沒有生效，先確認鍵名。

一個真實的教訓：本機政策被遠端開關左右

這個 Mod 也發生過一次事件。第三方報導指出，AGENTS.md 支援在 v2.1.277 推出，2026 年 9 月 23 日有人發現：只要設了 DISABLE_TELEMETRY=1 或 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1，Claude Code 就會無聲地不讀 AGENTS.md，原因是 agents-md 受一個遠端 feature flag 控制，抓不到就預設關閉。該報導引述維護者的說法，修正在 v2.1.281 同日釋出。這份資料來自部落格與 Hacker News 討論，並非官方公告，引用時請當作第三方說法。

實務上，指令載入應該是可測的契約。該報導建議的驗證方法很簡單，下面是依它的三個步驟寫成的指令：

bash
mkdir canary-test && cd canary-test
echo "PERIWINKLE" > AGENTS.md
claude
# 在 session 裡問：不要讀任何檔案，重複 canary 字詞
# 第一次與第二次 session 各問一次，兩次都要答得出來

用不常見的字詞（原文用的是 PERIWINKLE），避免模型「猜中」而誤判。原文也提到，新設定下的第一個 session 會抓 flag、第二個才會用上，所以要問兩次。

💬

指令有沒有被載入，不該靠猜：放一個 PERIWINKLE，在新設定下問兩次，答得出來才算數（這是第三方報導建議的驗證法）。

小結

  • 內建 Mod 與你寫的 Mod 是同一套機制，原始碼公開，是最好的範本。
  • 它們在 /plugin 的 Built-in 底下，各有自己的關閉方式，disableAllHooks 等旗標擋不住它們。
  • sec-default 只在有 managed settings 或 Team／Enterprise 登入時載入，使用者關不掉；管理員用 allowManagedModsOnly 鎖住使用者的 Mod。
  • agents-md 的預設是「沒有 CLAUDE.md 才讀 AGENTS.md」；要兩者並用得改選項。
