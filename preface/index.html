前言

前言

Claude Code 已經有 hooks、skills、plugins 與 MCP，Mods 多做了什麼，又多了哪些風險？

這本書在談什麼

從 Claude Code v2.1.287 開始，多了一種叫 Mods 的機制：用 JavaScript 或 TypeScript 寫的事件處理函式，跑在 Claude Code 程序內部。它能畫出可操作的面板、重繪 Claude Code 自己畫的部分、攔下或改寫 tool call 與 prompt，也能新增 slash command，這些是設定檔裡的 hook 做不到的。代價是 Mod 沒有沙箱，以你的權限執行。

這本書分成三條線：怎麼用（安裝、內建與社群 Mod）、怎麼寫（請 Claude 代寫、手寫、事件與 API、測試與分享）、怎麼管（安全邊界與團隊導入）。讀完之後，你應該能判斷一件事該不該寫成 Mod、能裝一個並看懂它會做什麼、能寫出自己的第一個 Mod，也能替團隊訂出審查與管控的規則。

資料從哪裡來

Mods 很新，多數資料出自 2026 年 9 至 10 月，官方文件、第三方報導與社群文章的說法並不總是一致。本書的做法是：

  • 官方文件優先：Mods overview、Create a mod、managed settings 與內建 Mod 的 README 是主要依據，書中以「官方文件說」標示。
  • 第三方與研究者的說法照實標明：例如第 15 章引用的安全研究，會寫清楚是誰、什麼時候、展示了什麼，不把它當成官方結論。
  • 作者的判斷與實測另外標示：第 12、14 章的案例含作者在自己機器上的實測輸出；第 15 章把「作者推論」與其他來源分開，第 16 章的導入建議標為「作者判斷」，都不是官方規範。
  • 說法矛盾時並陳：不替讀者擇一，並附上各自的出處與日期。

這本書適合誰

  • 日常使用 Claude Code，想知道 Mods 能讓工作流更順在哪裡的人。
  • 打算用 TypeScript 寫外掛來擴充 Claude Code 的開發者。需要會讀基本的 JavaScript／TypeScript，不需要懂 Node.js 或前端框架，因為 Mod 的執行環境沒有 Node 也沒有 DOM。
  • 要評估 Mods 該不該進團隊、怎麼管權限與審查的 tech lead。

範例程式碼的限制

書中程式碼分三種來源：官方文件的範例、第三方文章整理的社群 Mod，以及作者自己的 Mod；各章會交代範例的來源與節錄方式。作者的案例在作者的機器上跑過，附上的輸出是當時看到的，版本與數字會隨 Claude Code 更新而變，請以你自己的 claude --version 與官方文件為準。社群 Mod 我只轉述文章的描述，沒有替你逐一審查原始碼，這是第 6 章與第 15 章一再提醒的事。素材沒有給的程式碼，本書不替你補。

素材不足之處

  • 第 5 章（內建 Mod）：主要依據官方 overview、內建 Mod 的 README；agents-md 的歷史事件另引用第三方報導。各選項的行為仍應對照所用版本核實。
  • 第 11 章（組合多個 Mod）：hook 順序與失敗處理依官方文件，noun contract 主要依內建 Mod 的 README；該 README 標示為 early access。本章也提醒讀者對照所用版本產生的型別宣告。
  • 第 16 章（團隊導入）：管控設定來自官方管理文件；導入順序與三種立場的取捨是作者判斷，不是官方建議，書中已標明。
  • 第 1 章的時間線：9 月的兩個日期來自報導與影片整理，我沒有找到官方文件佐證，書中已標明。
